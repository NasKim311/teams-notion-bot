# 버그·개선 목록

이 프로젝트의 알려진 버그와 개선 후보를 관리한다. (팀 이슈를 등록하는 Notion "SSG 이슈 트래커"와는 별개다.)

## 관리 방법
- **번호:** 버그는 `B`, 개선은 `I`로 시작한다. 번호는 다시 쓰지 않는다 (해결·취소된 번호도 비워 둔다).
- **우선순위:** 🔴 높음(실제로 생길 수 있고 데이터·등록에 영향) / 🟡 보통 / ⚪ 낮음
- **상태:** `열림` → `진행 중` → `해결` 또는 `보류`·`취소`(이유 기록)
- **새로 발견하면:** 재현 방법이나 근거와 함께 추가한다. 추측이면 "확인 안 됨"이라고 적는다.
- **해결하면:** 고치는 커밋에서 항목을 맨 아래 "해결됨" 표로 옮긴다 (지우지 않음). 커밋 메시지에 번호를 넣어 두면 `git log --grep="(B1)"`로 해당 커밋을 찾을 수 있다 (예: `fix(B1): CSS 색상 코드를 일감 번호로 잡지 않기`). 버그는 회귀 테스트와 함께 고친다.
- 코드를 고칠 때 관련 항목이 있으면 같은 커밋에서 상태를 바꾼다 (CLAUDE.md "함께 고칠 곳").

## 열린 항목

### 🔴 B3. 일부만 등록된 뒤 다시 미리보기하면 등록된 이슈가 또 등록됨
- **상태:** 열림 · 발견 2026-10-08 · 위치 `src/page/client.js` (`renderCards`, `preview`, `submit`)
- **재현 (코드 경로):** 이슈 2개 중 1번 성공·2번 실패 → "이슈별로 나눠 등록" 체크 변경 또는 "다시 붙여넣기 → 미리보기" → 카드가 새로 만들어져 1번 완료 표시가 사라짐 → 등록하면 1번이 한 번 더 등록된다.
- **함께:** 모두 성공한 뒤에도 나누기 체크를 바꿀 수 있어 등록 버튼 없는 카드가 다시 그려진다.
- **수정안:** 완료된 카드가 있으면 다시 미리보기를 막거나 확인받기. 또는 완료 정보를 유지해 다시 만든 카드에도 "등록됨" 표시.

### 🟡 I1. 업데이트 대상 페이지가 이슈 DB 소속인지 확인하지 않음
- **상태:** 열림 · 발견 2026-10-08 · 위치 `src/notion/pages.ts` (`appendUpdate`), `src/api/issues.ts`
- **근거:** `pageId`는 형식만 검사한다. 연결(teams-notion-bot)이 다른 DB에도 연결되어 있으면, 조작된 요청으로 그 DB의 페이지에 글을 붙일 수 있다. 비밀번호가 있어야 하므로 위험은 낮다. (처음 설정 때 "SSG FE 형상관리" DB ID로 `validation_error`가 났던 걸 보면 그쪽에도 연결되어 있었을 수 있음)
- **수정안:** `appendUpdate`에서 가져온 페이지의 `parent.database_id`가 `NOTION_DATABASE_ID`와 같은지 확인하고, 다르면 400.

### 🟡 I2. 중간에 실패하면 다시 시도할 때 중복이 생김
- **상태:** 열림 · 발견 2026-10-08 · 위치 `src/notion/pages.ts` (`createNotionPage`, `appendUpdate`)
- **근거:** 새 이슈는 블록 100개를 넘는 나머지를 붙이다 실패해도 페이지는 이미 생성됨. 업데이트는 본문을 붙인 뒤 상태 변경이 실패해도 본문은 이미 붙음. 사용자는 오류를 보고 다시 누르므로 중복된다. 블록 100개 초과·상태 변경 실패 모두 드물다.
- **수정안:** 오류 응답에 "페이지는 만들어졌을 수 있어요 + 링크"를 담거나, 뒤 단계만 서버에서 한 번 재시도.

### 🟡 I3. 유형 분류가 "버그"로 쏠림
- **상태:** 열림 · 발견 2026-10-08 · 위치 `src/issue/classify.ts` (`BUG_SIGNALS`)
- **근거:** "기대 동작", "발생"이 버그 신호라서 추천 양식으로 쓴 개선 제안도 버그로 분류된다.
- **수정안:** "좋을 것 같음", "제안", "리팩토링"처럼 개선 신호가 뚜렷하면 양식 라벨보다 우선. 실제 사례를 모아 테스트로 정한다.

### 🟡 I4. 비밀번호 시도 횟수 제한 없음
- **상태:** 열림 · 위치 운영 설정 (Cloudflare)
- **근거:** 공유 비밀번호 하나라 무차별 대입에 약하다.
- **수정안:** Cloudflare 속도 제한 규칙(`/api/*`), 또는 Cloudflare Access로 회사 이메일 인증을 앞에 두기.

### 🟡 I5. 로컬과 운영이 같은 Notion DB를 씀
- **상태:** 열림 · 위치 `.dev.vars`
- **근거:** 로컬 개발·확인 중 만든 페이지가 실제 DB에 섞인다.
- **수정안:** 테스트용 DB를 따로 만들고 `.dev.vars`의 NOTION_DATABASE_ID만 바꾸기.

### 🟡 I6. 입력 화면 JS에 자동 테스트 없음
- **상태:** 열림 · 위치 `src/page/client.js`
- **근거:** 카드 렌더링, 이미지 유지, 순차 등록, 기존 이슈 선택이 수동 확인에만 의존한다 (Biome 린트는 적용됨). B3도 테스트가 있었으면 잡혔을 문제다.
- **수정안:** 브라우저 E2E(Playwright 등, devDependency)로 미리보기·등록 흐름을 가짜 fetch로 검증.

### ⚪ I7. 답글 작성자 이름에 괄호가 없으면 답글로 인식 못 함
- **상태:** 보류 (실제 사례가 생기면 진행) · 위치 `src/issue/header.ts` (`DISPLAY_NAME`)
- **근거:** 본문 중간 머리글은 `이름(직급) - 회사` 형태만 인정한다. 그 외 형태의 답글은 대화가 현상 섹션에 섞인다. 지금까지 본 팀 대화는 모두 괄호 형태다.

### ⚪ I8. 요청 본문을 다 읽은 뒤 크기 제한을 확인함
- **상태:** 열림 · 위치 `src/http/request.ts` (`readJson`)
- **근거:** 1MB 제한을 본문을 모두 읽은 뒤 확인한다. 비밀번호 확인 뒤라 외부 공격 경로는 아니고 메모리 측면의 작은 개선이다.
- **수정안:** `Content-Length`를 먼저 확인.

### ⚪ I9. Notion API 버전
- **상태:** 보류 · 위치 `src/notion/client.ts`, `scripts/lib/notion.ts`
- **근거:** `2022-06-28`로 동작한다. 최신 API의 data source 구조로 옮길 필요가 생기면 두 파일을 함께 바꾼다.

### ⚪ I10. 원격 저장소 백업
- **상태:** 열림
- **근거:** GitHub(`origin`)에 아직 push하지 않아 이 PC가 유일한 사본이다.

## 알려진 한계 (규칙 기반이라 생기는 것, 고칠 계획 없음)
- **긴 제목:** 문장이 길고 끊을 절이 없으면 60자를 넘는다 (100자까지). 미리보기 카드에서 고친다.
- **처음 보는 양식:** 모르는 라벨은 "참고"로, 라벨 없는 글은 "현상"으로 간다.
- **답글의 라벨 없는 내용은 본문에서 빠짐:** 중요한 답글은 `처리 상황 :` 같은 라벨을 붙여야 남는다.
- **Teams 원문 링크를 저장하지 않음:** 사용자 결정. 원문 대화로 돌아갈 방법이 없다.
- **기존 이슈 찾기는 레드마인 링크 일치만:** 일감 번호가 없는 이슈는 업데이트 대상으로 찾지 못한다.
