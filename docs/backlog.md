# 버그·개선 목록

이 프로젝트의 알려진 버그와 개선 후보를 관리한다. (팀 이슈를 등록하는 Notion "SSG 이슈 트래커"와는 별개다.)

## 관리 방법
- **번호:** 버그는 `B`, 개선은 `I`로 시작한다. 번호는 다시 쓰지 않는다 (해결·취소된 번호도 비워 둔다).
- **우선순위:** 🔴 높음(실제로 생길 수 있고 데이터·등록에 영향) / 🟡 보통 / ⚪ 낮음
- **상태:** `열림` → `진행 중` → `해결` 또는 `보류`·`취소`(이유 기록)
- **새로 발견하면:** 재현 방법이나 근거와 함께 추가한다. 추측이면 "확인 안 됨"이라고 적는다.
- **해결하면:** 고치는 커밋에서 항목을 맨 아래 "해결됨" 표로 옮긴다 (지우지 않음). 커밋 메시지에 번호를 넣어 두면 `git log --grep="(B1)"`로 해당 커밋을 찾을 수 있다 (예: `fix(B1): CSS 색상 코드를 일감 번호로 잡지 않기`). 버그는 회귀 테스트와 함께 고친다.
- 코드를 고칠 때 관련 항목이 있으면 같은 커밋에서 상태를 바꾼다 (CLAUDE.md "함께 고칠 곳").

## 열린 항목

### 🔴 B5. 팀 공지 양식의 예시 문구·구분선이 내용으로 등록됨
- **상태:** 열림 · 발견 2026-10-13 · 위치 `src/issue/structure.ts`, `src/issue/extract.ts` (`extractFiles`), `src/issue/parse.ts`
- **재현:** 팀원이 공지 양식을 복사해 현상만 채우고 나머지 예시를 그대로 두면 (2026-10-13 스크립트로 확인)
  - `📂 관련 파일 : 컴포넌트 경로:줄 번호 (예: src/views/fit/FitPage.tsx:75)` → 관련 파일에 예시 경로, 영역 `fit`, 제목 `[fit] …`
  - `🌐 테스트 URL : 문제가 생기는 화면 주소`, `🎯 기대 동작 : 원래 어떻게 동작해야 하는지` 같은 예시 문구가 본문 섹션 내용으로 남음
  - `━━━━━━ <이슈 공유 양식> ━━━━━━` 줄까지 복사하면 현상 섹션에 들어감
- **영향:** 팀원이 양식을 쓰기 시작하면 바로 생긴다. 컬럼(관련 파일·영역)과 제목이 틀리게 등록된다.
- **수정안:** 공지 양식의 예시 문구·구분선을 빼고, `(예: …)` 안의 경로는 관련 파일로 잡지 않기.

### 🔴 B6. 2000자가 넘는 URL이 본문에 있으면 등록 전체가 실패함
- **상태:** 열림 · 발견 2026-10-13 · 위치 `src/notion/blocks.ts` (`richText`)
- **재현:** 2000자가 넘는 URL은 링크 주소(`link.url`)로 그대로 보낸다 (스크립트로 확인: 2128자). Notion은 링크 주소 2000자 초과를 거부하므로 등록이 502로 실패한다. 드물다.
- **함께 볼 것:** 한글이 든 URL(`?q=신발`)도 인코딩하지 않고 링크로 보낸다. Notion이 받아 주는지는 **확인 안 됨**.
- **수정안:** 링크 주소는 `new URL(url).href`(인코딩된 주소)로 보내고, 2000자가 넘으면 링크 없이 글자로만 넣기.

### ⚪ I14. 테스트 URL 경로로 영역 추정

### 🔴 B4. "링크:"·"원문:" 줄은 Teams 링크가 아니어도 통째로 사라짐

- **재현:** `링크 : https://www.figma.com/file/abc 참고` → 본문에서 줄 전체가 빠지고 어디에도 저장되지 않는다. `원문: 디자인 가이드 3페이지`도 마찬가지.
- **영향:** Teams 링크를 저장하지 않기로 하면서 `링크:`/`원문:` 줄을 무조건 지우게 되어, 디자인 시안·문서 링크 같은 내용이 조용히 사라진다.

### 🟡 I1. 업데이트 대상 페이지가 이슈 DB 소속인지 확인하지 않음
- **상태:** 열림 · 발견 2026-10-08 · 위치 `src/notion/pages.ts` (`appendUpdate`), `src/api/issues.ts`
- **근거:** `pageId`는 형식만 검사한다. 연결(teams-notion-bot)이 다른 DB에도 연결되어 있으면, 조작된 요청으로 그 DB의 페이지에 글을 붙일 수 있다. 비밀번호가 있어야 하므로 위험은 낮다. (처음 설정 때 "SSG FE 형상관리" DB ID로 `validation_error`가 났던 걸 보면 그쪽에도 연결되어 있었을 수 있음)
- **수정안:** `appendUpdate`에서 가져온 페이지의 `parent.database_id`가 `NOTION_DATABASE_ID`와 같은지 확인하고, 다르면 400.

### 🟡 I2. 중간에 실패하면 다시 시도할 때 중복이 생김
- **상태:** 열림 · 발견 2026-10-08 · 위치 `src/notion/pages.ts` (`createNotionPage`, `appendUpdate`)
- **근거:** 새 이슈는 블록 100개를 넘는 나머지를 붙이다 실패해도 페이지는 이미 생성됨. 업데이트는 본문을 붙인 뒤 상태 변경이 실패해도 본문은 이미 붙음. 사용자는 오류를 보고 다시 누르므로 중복된다. 블록 100개 초과·상태 변경 실패 모두 드물다.
- **수정안:** 오류 응답에 "페이지는 만들어졌을 수 있어요 + 링크"를 담거나, 뒤 단계만 서버에서 한 번 재시도.

### 🔴 I11. 같은 일감인데 레드마인 링크 표기가 다르면 기존 이슈를 못 찾음
- **상태:** 열림 · 발견 2026-10-08 · 위치 `src/issue/extract.ts` (`extractWorkItem`), `src/notion/pages.ts` (`findExistingPages`)
- **재현:** 본문의 `https://redmine…/issues/11661`은 그대로 `https`로 저장되고, `#11661`은 설정값(`http://…/issues/`)으로 만들어진다. 기존 이슈 찾기는 링크가 글자 그대로 같아야 해서 서로 찾지 못한다.
  - 2026-10-13: 이슈↔결과 연결을 레드마인 일감으로 하고 관리자가 Notion에 링크를 **직접** 넣기로 해서 더 중요해졌다. 브라우저에서 복사한 `…/issues/11661#note-3`, `https://…`는 결과 공유의 `#11661`과 연결되지 않는다. 우선순위를 높였다.
- **영향:** 같은 일감인데 "기존 이슈에 추가" 후보가 안 나와 새 이슈가 중복 생성될 수 있다.
- **수정안:** 레드마인 링크는 항상 `REDMINE_ISSUE_URL` + 번호로 통일 (호스트가 같으면 번호만 뽑아 다시 만들기).

## 알려진 한계 (규칙 기반이라 생기는 것, 고칠 계획 없음)
- **긴 제목:** 문장이 길고 끊을 절이 없으면 60자를 넘는다 (100자까지). 미리보기 카드에서 고친다.
- **처음 보는 양식:** 모르는 라벨은 "참고"로, 라벨 없는 글은 "현상"으로 간다.
- **같은 사람이 똑같은 문장을 다시 쓰면 처리한 메시지로 보고 뺀다:** 시간 표시를 쓰지 않기 때문이다. 이슈 대화에서는 드물고, 체크를 끄면 포함된다. 처리한 뒤 편집된 메시지는 새 메시지로 본다.
- **답글의 라벨 없는 내용은 본문에서 빠짐:** 중요한 답글은 `처리 상황 :` 같은 라벨을 붙여야 남는다.
- **Teams 원문 링크를 저장하지 않음:** 사용자 결정. 원문 대화로 돌아갈 방법이 없다.
- **기존 이슈 찾기는 레드마인 링크 일치만:** 일감 번호가 없는 이슈는 업데이트 대상으로 찾지 못한다.
