# 결정 기록

이미 검토하고 버린 방안을 다시 제안하지 않도록, 주요 결정과 이유를 남긴다. 결정이 바뀌면 이 문서를 고친다.

## Teams 연동 대신 붙여넣기 웹 폼 (2026-10-07)
- 이슈 출처는 Teams **그룹 채팅**("[FE] 단기 프로젝트 이슈 대응")이다. 채널이 아니다.
- 검토하고 버린 방안:
  - **Outgoing Webhook**: 팀 표준 채널에서만 동작한다. 그룹 채팅·비공개 채널은 안 된다.
  - **채널로 옮기기**: 사용자가 팀을 만들 수 없다 (회사 정책으로 막힘).
  - **Power Automate → Worker**: 라이선스가 Free라 HTTP(프리미엄) 커넥터를 쓸 수 없다.
- 남은 유일한 진짜 연동 경로는 Teams 봇(Bot Framework)이고, IT 관리자 협조가 필요하다.
- 그래서 비밀번호로 보호하는 웹 폼(GET /)에 대화를 붙여넣고, 미리보기 후 등록하는 방식으로 바꿨다. Teams HMAC 코드는 제거했다.

## 제목은 AI 없이 규칙으로 만든다 (2026-10-08)
- Claude API 요약을 검토했지만 사용자가 원하지 않았다 ("특정 AI 지정해서 하지 말고"). 외부 AI 호출은 넣지 않는다.
- 양식: **`[영역] 요약`**. 영역이 없으면 `[FO]`/`[BO]`, 둘 다 없으면 요약만. 파일명은 제목에 넣지 않는다 (관련 파일 컬럼에 있음).
  - 다른 후보였던 "화면명 - 요약", "#일감 요약"은 선택되지 않았다.
- **`…`로 자르지 않는다.** 60자를 넘으면 그 안에서 끝나는 절까지 쓰고 명사형으로 끝맺는다. 끊을 곳이 없으면 100자까지 그대로 둔다.
- "~하고"에서는 끊지 않는다. "추가하고 입력하지 않을 경우"처럼 조건이 이어지는 경우가 많아, 끊으면 뜻이 바뀐다.
- 요약 정리: 괄호 부연, `->` 뒷부분, 인사·전달 문장을 빼고, 추측·존댓말 어미("설정된 것으로 보임", "출력됩니다")는 "설정됨", "출력됨"으로 바꾼다.
- `제목:` 필드로 사람이 직접 쓴 제목은 손대지 않는다.
- 규칙으로 명확해지지 않는 제목은 미리보기 카드나 Notion에서 사람이 고친다. 기존 페이지 중 2건은 직접 다듬은 제목이다 (`notion:retitle`로 덮어쓰지 말 것 → [notion.md](notion.md)).

## 새 이슈 본문은 고정 틀로 정리한다 (2026-10-08)
- 다른 후보였던 "요약 박스 + 원문 토글", "대화 타임라인" 대신 **고정 틀**이 선택되었다. 모든 페이지가 같은 모양이라 훑어보기 쉽다.
- 순서: 🐞 현상 → 🎯 기대 동작 → 🔍 원인 → 🛠 처리·해결 → 📎 참고 → 💬 대화 기록. 내용이 없는 섹션은 생략한다.
- 라벨 매핑 (`src/structure.ts`):
  - 이슈 사항/이슈/이슈 현상/현상/문제점/이슈 N) → 현상. 경로/위치/재현은 현상 안에 "▸ 라벨" 줄로 넣는다.
  - 이슈 원인/이슈 발생 원인/원인 → 원인.
  - 해결/해결 방법/이슈 해결/처리 상황/개선 → 처리·해결.
  - 관련 추가 이슈/우려/모르는 라벨 → 참고 ("▸ 라벨" 줄과 함께).
  - 브랜치명/Merge Request → 값은 컬럼에만 넣는다. 설명이 붙은 줄만 참고로 보낸다.
- 첫 메시지에서 라벨 없이 쓴 글은 현상으로 보낸다. 이후 답글(본문 중간 머리글)의 라벨 없는 글은 대화 기록으로, 라벨이 있는 글은 해당 섹션으로 보낸다.
- 브랜치명, MR·레드마인 링크만 있는 줄은 본문에서 뺀다 (컬럼에 있음).
- **새 이슈를 만들 때만 정리한다.** "기존 이슈에 업데이트로 추가"는 원문 그대로 붙인다. 후속 글("수정 완료했습니다")이 현상으로 분류되는 것을 막기 위해서다.
- 미리보기 카드의 본문은 정리 전 원문이다. 정리는 등록할 때 서버에서 한다 (`newIssueBlocks`).
- 2026-10-08 이전에 등록된 페이지는 옛 형식(원문 그대로)이다.

## Teams 메시지 링크는 저장하지 않는다 (2026-10-08)
- 사용자가 DB에서 "원문 링크" 컬럼을 지웠고, 링크를 본문에 남기는 대신 "완전히 제거"를 골랐다.
- `링크:`/`원문:` 줄과 링크만 있는 줄은 본문에서 뺀다. 문장 속 링크는 그대로 둔다.
- 기존 이슈 찾기(업데이트로 추가)는 **레드마인 링크가 같은 페이지**로만 한다.

## FO/BO는 본문에서 추정한다 (2026-10-08)
- 본문에 대문자 `FO`/`BO`, "프론트 오피스"/"백오피스"가 나오면 처음 나온 것을 쓴다. URL 안의 글자(`.bo.`)는 무시한다.
- 미리보기 카드에서 고칠 수 있다.

## 작성자는 이름만, select로 (2026-10-08)
- DB의 작성자 컬럼이 select로 바뀌었다. Teams 표시 이름 "정주영(사원) - 유젠"에서 "정주영"만 저장한다.
- select 옵션 이름에는 쉼표가 들어갈 수 없어서 공백으로 바꾼다. 목록에 없는 이름이면 Notion이 옵션을 자동으로 만든다.

## 유형 분류 우선순위
- 태그(`[버그]`/`[개선]`/`[운영]`)가 있으면 그대로 쓴다. 없으면 신호 단어로 **버그 > 운영 > 개선 > 기타** 순서로 고른다.

## 범위 밖
- 외부 AI(요약·분류), 레드마인 링크 일치 외의 중복 감지, Teams 실시간 연동.
