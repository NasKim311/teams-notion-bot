# 결정 기록

이미 검토하고 버린 방안을 다시 제안하지 않도록, 주요 결정과 이유를 남긴다. 결정이 바뀌면 이 문서를 고친다.

## Teams 연동 대신 붙여넣기 웹 폼 (2026-10-07)
- 이슈 출처는 Teams **그룹 채팅**("[FE] 단기 프로젝트 이슈 대응")이다. 채널이 아니다.
- 검토하고 버린 방안:
  - **Outgoing Webhook**: 팀 표준 채널에서만 동작한다. 그룹 채팅·비공개 채널은 안 된다.
  - **채널로 옮기기**: 사용자가 팀을 만들 수 없다 (회사 정책으로 막힘).
  - **Power Automate → Worker**: 라이선스가 Free라 HTTP(프리미엄) 커넥터를 쓸 수 없다.
- 남은 유일한 진짜 연동 경로는 Teams 봇(Bot Framework)이고, IT 관리자 협조가 필요하다.
- 그래서 비밀번호로 보호하는 웹 폼(GET /)에 대화를 붙여넣고, 미리보기 후 등록하는 방식으로 바꿨다. Teams HMAC 코드는 제거했다.

## 제목은 AI 없이 규칙으로 만든다 (2026-10-08)
- Claude API 요약을 검토했지만 사용자가 원하지 않았다 ("특정 AI 지정해서 하지 말고"). 외부 AI 호출은 넣지 않는다.
- 양식: **`[영역] 요약`**. 영역이 없으면 `[FO]`/`[BO]`, 둘 다 없으면 요약만. 파일명은 제목에 넣지 않는다 (관련 파일 컬럼에 있음).
  - 다른 후보였던 "화면명 - 요약", "#일감 요약"은 선택되지 않았다.
- **`…`로 자르지 않는다.** 60자를 넘으면 그 안에서 끝나는 절까지 쓰고 명사형으로 끝맺는다. 끊을 곳이 없으면 100자까지 그대로 둔다.
- "~하고"에서는 끊지 않는다. "추가하고 입력하지 않을 경우"처럼 조건이 이어지는 경우가 많아, 끊으면 뜻이 바뀐다.
- 요약 정리: 괄호 부연, `->` 뒷부분, 인사·전달 문장을 빼고, 추측·존댓말 어미("설정된 것으로 보임", "출력됩니다")는 "설정됨", "출력됨"으로 바꾼다.
- `제목:` 필드로 사람이 직접 쓴 제목은 손대지 않는다.
- 규칙으로 명확해지지 않는 제목은 미리보기 카드나 Notion에서 사람이 고친다. 기존 페이지 중 2건은 직접 다듬은 제목이다 (`notion:retitle`로 덮어쓰지 말 것 → [notion.md](notion.md)).

## 새 이슈 본문은 고정 틀로 정리한다 (2026-10-08)
- 다른 후보였던 "요약 박스 + 원문 토글", "대화 타임라인" 대신 **고정 틀**이 선택되었다. 모든 페이지가 같은 모양이라 훑어보기 쉽다.
- 순서: 🐞 현상 → 🌐 테스트 URL → 🔍 원인 → 🛠 처리·해결 → 🎯 기대 동작 → 📎 참고(이미지 등 참고할만한 자료).
  - 2026-10-13 사용자 결정으로 테스트 URL 섹션을 현상 다음에 추가했다. **Notion 컬럼은 만들지 않고 본문에만** 둔다 (사용자 결정). 다른 후보였던 "현상 안에 ▸ 줄"보다 눈에 잘 띄는 별도 섹션을 골랐다. 라벨 이름은 "테스트 경로"보다 파일 경로와 헷갈리지 않는 "테스트 URL"로 했다 (둘 다 인식).
  - 2026-10-12 사용자 결정으로 기대 동작을 처리·해결 뒤로 옮기고, 참고 제목에 "이미지 등"을 붙였다. 스크린샷은 본문 맨 뒤(참고 아래)에 붙는다.
  - 처음(2026-10-08) 순서는 현상 → 기대 동작 → 원인 → 처리·해결 → 참고였다.
- **내용이 없어도 여섯 섹션 제목은 모두 넣는다** (사용자 결정, 2026-10-08). 나중에 Notion에서 채울 수 있게 하기 위해서다.
  - 제목 요약은 현상 섹션에서 찾고, 현상이 비어 있으면 본문 전체에서 찾는다.
- 라벨 매핑 (`src/issue/structure.ts`):
  - 이슈 사항/이슈/이슈 현상/현상/문제점/이슈 N) → 현상. 경로/위치/재현은 현상 안에 "▸ 라벨" 줄로 넣는다.
  - 테스트 URL/테스트 경로 → 테스트 URL (주소가 여러 개면 모두).
  - 이슈 원인/이슈 발생 원인/원인 → 원인.
  - 해결/해결 방법/이슈 해결/처리 상황/개선 → 처리·해결.
  - 관련 추가 이슈/우려/모르는 라벨 → 참고 ("▸ 라벨" 줄과 함께).
  - 브랜치명/Merge Request/관련 파일 → 값은 컬럼에만 넣는다. 설명이 붙은 줄만 참고로 보낸다.
  - 팀 공유 양식처럼 이모지로 시작하는 제목("🐞 현상", "📂 관련 파일")은 `:` 없이 혼자 써도 라벨로 본다. 이모지 없는 "현상" 한 단어 줄은 내용일 수 있어 라벨로 보지 않는다.
- 첫 메시지에서 라벨 없이 쓴 글은 현상으로 보낸다. 답글(본문 중간 머리글 뒤)에 라벨이 있는 글은 해당 섹션으로 보낸다.
- **대화 기록은 넣지 않는다** (사용자 결정, 2026-10-08). Teams 머리글(작성자·시간)과 답글의 라벨 없는 글은 본문에서 빠진다. 작성자는 컬럼에 있다.
- 브랜치명, MR·레드마인 링크만 있는 줄은 본문에서 뺀다 (컬럼에 있음).
- **새 이슈를 만들 때만 정리한다.** "기존 이슈에 업데이트로 추가"는 원문 그대로 붙인다. 후속 글("수정 완료했습니다")이 현상으로 분류되는 것을 막기 위해서다.
- 미리보기 카드의 본문은 정리 전 원문이다. 정리는 등록할 때 서버에서 한다 (`newIssueBlocks`).
- 기존 페이지도 `npm run notion:restructure`로 새 틀로 바꿨다 (2026-10-08 13건, 2026-10-12 순서·참고 제목 변경, 2026-10-13 테스트 URL 섹션 추가. 스크린샷·업데이트는 그대로).

## 이미 처리한 메시지는 다음 붙여넣기에서 뺀다 (2026-10-08)
- 채팅방을 넉넉히 복사해 붙여넣어도, 전에 등록한 메시지는 빼고 새 메시지만 정리한다.
- **Teams에서 직접 가져오기는 하지 않는다.**
  - 채팅 URL(딥 링크)은 로그인 화면으로만 이어지고, 메시지는 Microsoft Graph API(`/chats/{id}/messages`)로만 읽을 수 있다.
  - Graph Explorer로 이 채팅방 메시지를 읽을 수 있음은 확인했다 (`Chat.Read`는 관리자 승인 불필요).
  - 다만 우리 앱으로 쓰려면 회사 Entra ID에 앱을 등록해야 하고, 이 도구는 회사 승인 없이 팀 안에서만 쓰므로 등록하지 않기로 했다. 회사 승인이 나면 같은 제외 로직에 "가져오기"만 붙이면 된다.
- 메시지 구분: Teams 머리글 기준으로 나누고, 같은 메시지 판단은 **작성자 + 내용**으로 한다. 시간 표시("오후 1:25", "어제 …")는 복사한 날마다 달라 쓰지 않는다 (`src/issue/messages.ts`).
- 기록: 메시지 **지문(SHA-256)만** Cloudflare KV(`PROCESSED_MESSAGES`)에 1년간 저장한다. 원문은 저장하지 않는다 (`src/store/processed.ts`).
- 기록 시점: 카드 등록이 **모두** 끝났을 때만 기록한다 ("등록 안 함"으로 둔 카드의 메시지 포함). 일부만 성공하고 끝나면 기록하지 않아, 다음에 다시 보이는 쪽(놓치지 않는 쪽)을 택했다.
- 입력 화면의 "이전에 처리한 메시지 제외" 체크(기본 켜짐)를 끄면 모두 포함한다.

## Teams 메시지 링크는 저장하지 않는다 (2026-10-08)
- 사용자가 DB에서 "원문 링크" 컬럼을 지웠고, 링크를 본문에 남기는 대신 "완전히 제거"를 골랐다.
- `링크:`/`원문:` 줄과 링크만 있는 줄은 본문에서 뺀다. 문장 속 링크는 그대로 둔다.
- 기존 이슈 찾기(업데이트로 추가)는 **레드마인 링크가 같은 페이지**로만 한다.

## FO/BO는 본문에서 추정한다 (2026-10-08)
- 본문에 대문자 `FO`/`BO`, "프론트 오피스"/"백오피스"가 나오면 처음 나온 것을 쓴다. URL 안의 글자(`.bo.`)는 무시한다.
- 미리보기 카드에서 고칠 수 있다.

## 작성자는 이름만, select로 (2026-10-08)
- DB의 작성자 컬럼이 select로 바뀌었다. Teams 표시 이름 "정주영(사원) - 유젠"에서 "정주영"만 저장한다.
- select 옵션 이름에는 쉼표가 들어갈 수 없어서 공백으로 바꾼다. 목록에 없는 이름이면 Notion이 옵션을 자동으로 만든다.

## 운영 배포 버전은 태그와 기록 문서로 관리한다 (2026-10-08)
- 다른 후보였던 "SemVer + CHANGELOG"는 팀 내부 도구에 무거워서, "git 태그 + Cloudflare 버전 메시지 + 배포 기록 문서"를 골랐다 (사용자 결정).
- 이름: `deploy-날짜.순번` (한국 시간, 예: `deploy-2026-10-08.3`). git 태그, Cloudflare 버전 태그, [deployments.md](deployments.md) 항목이 모두 같은 이름이다.
- 배포는 커밋이 끝난 `main`에서만 한다. 커밋 안 된 코드가 배포되면 기록과 실제가 달라지기 때문이다.
- 기록의 "바뀐 것"은 이전 배포 이후의 `feat`/`fix` 커밋 제목으로 자동으로 만든다. 따로 쓰지 않아도 되게 하기 위해서다.

## 팀 공유 절차와 결과 연결 (2026-10-12)
- 팀원은 Teams에 <이슈 공유 양식>(현상/테스트 URL/원인/처리·해결/기대 동작/관련 파일/참고)과 <결과 공유 양식>(레드마인 일감/브랜치 명/처리 내용)으로 올린다. 봇은 관리자 한 명만 쓴다.
- 이슈와 결과는 **레드마인 일감 번호**로 연결한다 (사용자 결정). "Notion 번호를 공통 키로" 하는 방안은 공지문을 단순하게 하려고 쓰지 않았다.
  - 이슈 공유를 등록할 때는 아직 일감이 없으므로, 일감을 만들 때 관리자가 Notion 페이지의 레드마인 링크를 **직접** 넣는다 (코드 변경 없음).
  - 결과 공유를 붙여넣으면 같은 레드마인 링크의 페이지가 "기존 이슈에 추가" 후보로 나온다.

## 유형 분류 우선순위
- 태그(`[버그]`/`[개선]`/`[운영]`)가 있으면 그대로 쓴다. 없으면 신호 단어로 **버그 > 운영 > 개선 > 기타** 순서로 고른다.
