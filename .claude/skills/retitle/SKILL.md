# 기존 이슈 제목 다시 만들기

Notion의 실제 데이터를 바꾸는 작업이다. **미리보기 → 사용자 확인 → 적용(자동 백업) → 다시 조회** 순서를 지킨다.
제목 규칙과 그 이유: [docs/decisions.md](../../../docs/decisions.md) "제목은 AI 없이 규칙으로 만든다"

## 1. 미리보기 (아무것도 바꾸지 않음)
```
npm run notion:retitle
```
- 각 페이지가 `[변경]` / `[같음]` / `[건너뜀]`과 함께 `이전 → 새 제목`으로 나온다.
- 본문은 Notion 블록에서 다시 만든 텍스트라 원래 붙여넣기와 조금 다르다. 소제목은 "라벨 :"이 되고, 업데이트(구분선) 뒤 내용은 제외된다.

## 2. 사람이 직접 고친 제목을 확인한다
- `docs/notion.md`의 "직접 다듬은" 목록에 있는 제목은 덮어쓰지 않는다.
- 사용자가 Notion에서 고친 것으로 보이는 제목(봇 규칙으로 나올 수 없는 표현)도 덮어쓰지 않는다. 애매하면 사용자에게 묻는다.
- 이런 페이지의 ID를 `--skip`에 모은다.

## 3. 사용자에게 변경 목록을 보여주고 확인받는다
- `이전 → 새` 표로 보여준다. 규칙 결과가 오히려 나빠지는 건(뜻이 바뀜, 지나치게 김)은 따로 짚는다.
- 사용자가 요청한 범위(예: "…로 끝나는 것만")가 있으면 그 범위만 적용한다. 나머지는 `--skip`으로 뺀다.

## 4. 적용
```
npm run notion:retitle -- --apply --skip <페이지ID,페이지ID>
```
- 이전 제목은 `scripts/.backups/titles-<시각>.json`에 자동으로 백업된다 (git 제외).
- 규칙으로 명확해지지 않는 제목을 사람이 쓴 것처럼 직접 다듬어 넣었다면, 그 사실을 사용자에게 알리고 `docs/notion.md`의 직접 다듬은 목록에 추가한다.

## 5. 확인
- `npm run notion:retitle`을 다시 돌려 적용한 페이지가 `[같음]`으로 나오는지 본다.
- 결과 목록과 백업 위치를 사용자에게 알린다. 되돌리기는 백업 JSON의 `old` 값으로 같은 방식으로 PATCH하면 된다.
