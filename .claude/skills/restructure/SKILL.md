# 기존 이슈 본문 다시 쓰기

Notion 페이지 본문을 지우고 새로 쓰는 작업이다. **미리보기 → 검토 → 적용(자동 백업) → 다시 확인** 순서를 지킨다.
본문 틀과 그 이유: [docs/decisions.md](../../../docs/decisions.md) "새 이슈 본문은 고정 틀로 정리한다"

## 무엇을 바꾸고 무엇을 두는가 (`scripts/restructure.ts`)
- 처음 등록된 본문(첫 구분선 앞)의 **글 블록**(문단·소제목·코드)만 다시 쓴다.
- **스크린샷(이미지)과 업데이트(구분선 뒤)는 그대로** 둔다. 새 글 블록은 기존 글 블록 자리, 즉 이미지 앞에 들어간다.
- 봇이 만들지 않은 블록(토글·목록·콜아웃 등), 하위 블록이 있는 블록, 이미지 뒤에 글이 있는 페이지는 사람이 손댄 것으로 보고 `[건너뜀]`으로 처리한다.
- 이미 현재 틀인 페이지는 `[같음]`으로 나온다. 다시 돌려도 안전하다.

## 1. 미리보기
```
npm run notion:restructure
```
- 전체 이전/이후 비교가 `scripts/.backups/restructure-preview-<시각>.txt`에 저장된다. 이 파일을 읽고 검토한다.

## 2. 검토할 것
- **본문에서 빠지는 정보:** 브랜치명과 MR·레드마인 링크만 있는 줄, Teams 머리글, 답글의 라벨 없는 대화는 빠진다.
  - 브랜치·링크 줄이 빠지는 페이지는 해당 컬럼(브랜치 명·레드마인 링크·MR 링크)에 값이 있는지 확인한다. 비어 있으면 정보가 사라지므로 사용자에게 알린다.
- 라벨이 엉뚱한 섹션으로 가거나 코드가 문단으로 바뀌는 등 이상한 결과가 있으면 적용 전에 사용자에게 보여준다.
- `[건너뜀]` 페이지와 그 이유를 사용자에게 알린다.

## 3. 적용
```
npm run notion:restructure -- --apply [--skip <페이지ID,...>]
```
- 원본 글 블록은 `scripts/.backups/bodies-<시각>.json`에 백업된다 (git 제외). 지운 블록은 Notion 페이지 기록에서도 되살릴 수 있다.

## 4. 확인
- `npm run notion:restructure`를 다시 돌려 모두 `[같음]`으로 나오는지 본다.
- 이미지가 본문 뒤에 남아 있는지 확인한다. 페이지별 블록 순서는 `scripts/lib/body.ts`의 `listChildren`으로 조회할 수 있다.
- 결과와 백업 위치를 사용자에게 알린다.
